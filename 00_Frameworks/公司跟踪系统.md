# 框架 · 公司跟踪系统(模块化架构)

> 把"跟踪一家公司"从**一次性 deep-dive 单体**,拆成**模块化、可独立调度的子智能体系统**。
> 上承 [[护城河论点引擎]](L3 方法)+ [[瓶颈轮动框架]](L0–L2 宏观);产物落 `10_Stocks/X.md`。
> 本文是**架构蓝图**(怎么搭),不是方法论(怎么想)、也不是 schema(往哪填)。

> **一句话**:**护城河模块发"考卷"(可证伪预言 + 监控仪表盘),其余模块"答题"(用事件给预言投票)。** 模块不是平行独立体,是**有向依赖 + 双节奏**。

## 3 · 依赖图(为什么不是 5 个独立体)

```
慢层(季度 / 触发才重跑)                    快层(日 / 周)
──────────────────────                     ────────────────────────
 M1 公司基本盘                               M5 技术·催化 ──(催化日)──┐
      │                                                              ▼
      ▼                                      M6 新闻事件流 ◄──────────┘(找到日期,M6 解释)
 M2 护城河 ───发「考卷」──►  可证伪预言清单 + 监控仪表盘
      │                            ▲                │
      ▼                            │                ▼ (M4 / M6 给预言投票)
 M3 估值锚 ◄── M4 财务跟踪 ─────────┘          里程碑状态机
                                                    │
                          票打穿预言 / 到季度 ───────┘──► 触发慢层重跑
```

**三条硬依赖(破坏任何一条 = 退化成无意义的并行)**:
1. **M2 发考卷,M4/M6 答题** —— 护城河模块吐出预言 + 仪表盘,事件模块拿事件投票。这是 [[护城河论点引擎]] §8 的输出契约。
2. **M5 找日期 → M6 解释** —— 技术模块**不做通用 TA**,只产催化日(个股超额异动日)+ 趋势段,把日期喂给 M6。
3. **M3 消费 M2 + M4** —— 估值要先有护城河(增长来源)和财务(兑现度)才能反推 price-in。

## 4 · 双节奏(决定调度与成本)

| 层 | 模块 | 重跑频率 | 触发 | 成本 |
|---|---|---|---|---|
| **慢层** | M1 / M2 / M3 | 季度,或预言被打破时 | 里程碑状态=落空 / 季度 / 论点 `version+1` | 贵,少跑 |
| **快层** | M4 / M5 / M6 | 日 / 周 | 排程 + 新事件到达 | 便宜,常跑 |

> **铁律:别每天重算护城河。** 慢层是常驻假设,只有被快层的票打穿、或到季度复盘,才重跑。

---

## 5 · 编排两模式

**A. 创世跑(GENESIS — 新股票首次建卡)**
`M1 → M2 → M3`(慢层串,M3 等 M2/M4)→ `M4 / M5 / M6`(快层并)→ 组装整篇 `10_Stocks/X.md`。
> ≈ 现在的 deep-dive skill,只是从单体拆成了模块扇出。

**B. 维护跑(MAINTENANCE — 老股票持续跟踪)**
只调度快层 `M4 / M5 / M6`(排程 + 事件触发)→ 更新 Part 2 事件流 + 里程碑状态。
**只有当某张票打穿 M2 的预言、或到季度,才回头重跑慢层**(并 `version+1`)。

---

## 6 · 触发器与里程碑状态机

快层的票不是写完就算,要驱动状态机(沿用 [[护城河论点-T]] 的里程碑状态):

```
待定 ──► 进行中 ──► 已兑现   (确认票累积)
   │         │
   └─────────┴──► 落空     (否决票打穿预言) ──► 触发慢层 M2/M3 重跑 + version+1
                   作废     (前提失效)
```

> **这是整个系统的反馈闭环**:慢层发预言 → 快层投票 → 票打穿 → 慢层重估。没有这个闭环,就只是"定期生成报告",不是"跟踪"。

## 8 · 实现路径(分阶段,先快层后编排)

- **Phase 0(已在)**:GENESIS 单体 = 现有 deep-dive skill。能用,先不拆。
- **Phase 1**:把 **M6 新闻事件流**独立成第一个模块(频率最高、价值最清晰、契约最明确)——输入=M2 的预言清单,输出=票 + 状态更新。
- **Phase 2**:**M4 财务跟踪**(数据已在 PG/DDB,只差解读层 + 投票)。
- **Phase 3**:**编排器(Workflow)** 实现 GENESIS 全模块扇出 + MAINTENANCE 定时调度。
- **Phase 4**:M1/M2/M3 慢层逐步从 deep-dive 单体里抽出成独立模块。

> 原则:**先做快层单模块(M6→M4)跑通投票闭环,再上编排**。别一上来就搭全套 orchestrator。

## 9 · 输出物

组装后的 `10_Stocks/X.md`,遵循 [[护城河论点-T]] schema:
- **Part 1(慢)** = M1+M2+M3 → 护城河论点 + 三档裁决 + 可证伪预言。
- **Part 2(快)** = M4+M5+M6 → 事件流 + 里程碑状态 + 容错度 + 前瞻日历。
